# 计算器设计与实现说明

本文整理这台 STM32 计算器的硬件配置、软件结构、功能与验证方式。
作者提供的 `README.md`（根目录与 `example/`）描述的是原始示例，本文描述的是本工程的实际实现。

## 1. 硬件与引脚

| 项目 | 配置 |
| --- | --- |
| MCU | STM32F103C8T6，HSE 8 MHz × PLL9 = 72 MHz；APB1 = 36 MHz |
| 显示 | LCD1602，4 位模式：RS = PB10，E = PB11，D4–D7 = PB12–PB15 |
| 触摸 | 两片 TTP229，各 16 通道，共 30 个按键：A 片 SCL = PB6 / SDO = PB7，B 片 SCL = PB8 / SDO = PB9 |
| 串口 | USB CDC 虚拟串口（PA11 / PA12），与供电共用 Type-C |
| 指示灯 | PC13，500 ms 翻转一次，作为运行心跳 |
| 时基 | TIM3 预分频 71 → 1 MHz，用读 CNT 的方式产生微秒延时；HAL 毫秒时基走 TIM4 |

TTP229 用 GPIO 软件模拟两线时序，不是标准 I²C：SCL 拉低 → 等 5 µs → 采 SDO → 拉高 → 等 5 µs，
每片读 16 个通道；两片共 32 个通道，按通道→键号映射表合成 30 位按键位图
（键位与作者库一致，所以自己写的驱动可以直接替换原库）。

## 2. 软件结构

不使用 RTOS。初始化完成后在 `while (1)` 里轮流跑三件事，各自用 `HAL_GetTick()` 控制周期：

| 周期 | 工作 |
| --- | --- |
| 10 ms | 采样 TTP229 → 去抖 → 组合识别 → 得到按键号 → 交给界面状态机 |
| 20 ms | 取 USB CDC 收到的字节，更新串口显示内容 |
| 按需 | 刷新 LCD（内容或光标变了才写，靠影子缓冲去重，因为 LCD 写入很慢） |
| 500 ms | PC13 心跳 |

### 界面状态机

```
SCREEN_EXPR ──MODE──▶ SCREEN_MENU ──OK──▶ ANGLE UNIT / COMPLEX / POLAR
     ▲                     │               HISTORY  / SEND FROM PC
     └──── BACK / MODE ────┴── 设置页：方向键改暂存值，OK 提交，BACK / MODE 丢弃
```

- 设置项都有两份值：`setting_*` 生效值、`pending_*` 暂存值。
- OK 提交时重新应用：算式非空就按新设置重算，算式为空则把上一次结果按新格式重画。
- 提交后**直接回结果界面**（改设置的目的是马上看结果变成什么样），想继续改别的设置再按 MODE。
- 设置页不显示光标，用 `>` 表示"正在选"、`*` 表示"已生效"。

### 极坐标

极坐标固定以原点 `(0,0)` 为参考，`FMT` 在算式界面按一下就在 `a+bi` 和 `r∠θ`
之间切换，没有额外的原点输入页。

### 数据流

```
TTP229 → 去抖 → 组合识别 → 按键号 → 界面状态机 → 输入缓冲 / 设置项
                                                      ↓ EXE
                              表达式字符串 → calculator_engine → 复数结果
                                                      ↓
                                       calc_format → 第 2 行文本 → LCD
                                                      ↓
                                             calc_history（最近 8 条）
```

## 3. 按键与输入

| 键号 | 无 SHIFT | SHIFT | 键号 | 无 SHIFT | SHIFT |
| --- | --- | --- | --- | --- | --- |
| 00 | SHIFT | — | 15–17 | 4 5 6 | e log(,) ln() |
| 01 | BACK（清整行） | — | 18 | `*` | `()^()` 或 `^()` |
| 02 | MODE（打开菜单） | — | 19 | `/` | `sqrt()` |
| 03 / 07 / 08 / 09 | ↑ / ← / ↓ / → 移动光标 | — | 20–22 | 1 2 3 | `s()` `c()` `t()` |
| 04 | OK（菜单确认，算式界面无动作） | — | 23 / 24 | `+` / `-` | — |
| 05 / 06 | `(` / `)` | — | 25 / 26 | `0` / `.` | — |
| 10–12 | 7 8 9 | π ∠ i | 27 | `E`（×10^x 的指数记号） | — |
| 13 | DEL（退格） | — | 28 | **FMT**：一键切 RECT ↔ POLAR | **ANS**：插入上一次结果 |
| 14 | AC（清空并回 READY） | — | 29 | EXE（求值） | — |

设计要点：

- 函数键插入的是完整模板（`s()`、`ln()`、`sqrt()`），右括号自带，光标直接停在括号里；若用户再按 `)`，只把光标移过现成的右括号，不插重复的。
- `x^y` 会判断光标左边是否已有操作数：有就插 `^()`，没有就插 `()^()` 并把 `)^(` 标成"方向键跳过"，这样在底数后面按一下 → 就能跳到指数。
- `log` 是二元函数，插入 `l(,)`，光标先停在第一个参数（底数）。
- SHIFT 锁存时结果行右端亮 `S`，提示下一个字符键走上档层。
- `2i` 这类隐式乘法不允许（必须写 `2*i`），否则 `2i^2` 的优先级会有歧义。

## 4. 计算能力

### 表达式语法

递归下降解析，优先级从低到高：

```
expression := term (('+' | '-') term)*
term       := polar (('*' | '/') polar)*
polar      := unary ('∠' unary)*          a∠b = a·e^{i·b}（b 按当前角度单位）
unary      := ('+' | '-') unary | power
power      := primary ('^' unary)?        右结合：2^3^2 = 512
primary    := 数字 | pi | e | A(Ans) | i | '(' expression ')' | 函数(参数)
```

| 记号 | 含义 | 记号 | 含义 |
| --- | --- | --- | --- |
| `s( c( t(` | sin / cos / tan | `n(` | ln |
| `l(a,b)` | log_a b（二元，两个参数都必须填） | `q(` | √ |
| `^` | 幂 | `E` | ×10^x（如 `1.5E3`） |
| `p i` | π | `e` | 自然常数 |
| `A` | 上一次的结果（Ans） | `i` | 虚数单位 |
| `∠` | 极坐标构造符（CGRAM 自定义字符） | | |

### 复数

引擎内部所有值都是 `a+bi`（实数即虚部为 0 的复数），运算都是复数运算：

- 四则、幂、开方、对数、指数都按复变函数的主值实现；三角函数按定义展开
  （`sin(a+bi) = sin a·cosh b + i·cos a·sinh b`，`tan = sin/cos`）。
- `∠` 支持复数幅值，`2∠30∠60` 会连乘；角本身带虚部（`2∠(3+4i)`）没有定义，报 Math ERROR。
- `COMP` 是"实数域机器"：输入出现 `i`/`∠` 或结果带虚部 → Math ERROR。
  `CMPLX` 是"复数域机器"：给出主值。开机默认 CMPLX。

### 结果显示

第 2 行固定 16 格，结果左边补 `=`：

- 实数：7 位有效数字，去尾随 0；绝对值 ≥ 1e7 或 < 1e-4 用科学计数法；小于 5e-7 当 0（消浮点残差）。
- 复数 RECT：`3+4i`，纯虚数写 `4i` / `-i`（不写 `0+`，也不写 `1i`）。
- 复数 POLAR：`5∠53.1301`，角度按当前单位；纯实数仍按实数写，不写成 `r∠0`。
- 实部/虚部按实际长度自适应分配 16 格，放得下就一位不丢（`1048576+3i`）；实在放不下才转科学计数法并压缩，绝不悄悄截断高位数字。
- 结果正好占满 16 格时省略 `=`，免得把末尾的 `i` 挤出屏幕。
- 显示用的角度单位只换算实部：`s(1+i)` 和 `asin` 类结果的虚部不随 DEG/RAD 变。

### 错误

| 提示 | 触发条件 |
| --- | --- |
| `Syntax ERROR` | 括号不配、运算符缺操作数、隐式乘法（`2i`）、表达式为空 |
| `Math ERROR` | 实数模式下出现复数；`tan` 在极点（`t(90)`）；域外（`ln(0)`）；结果非有限（溢出） |
| `Div0 ERROR` | 除以 0 |

## 5. 历史记录

- 环形缓冲保存最近 **8 条**（算式 + 结果），写满覆盖最旧的；只有按 EXE 成功求值才入账，改设置触发的重算不重复记账。
- `MODE → HISTORY` 进入：上下键翻条目（上是更旧），左右键横向滚长算式（一条最长 64 格），
  OK 把算式装回输入行，EXE 装入并立刻重算，BACK 回菜单、MODE 回算式界面。
- 第 1 行显示算式，第 2 行按**当前设置**重新格式化这条结果（切 DEG/RAD、RECT/POLAR 后跟着变），
  结果不长时右端补 `n/m` 位置提示；没有记录时显示 `HISTORY / EMPTY`。

## 6. 串口

USB CDC 枚举成一个虚拟串口，电脑端用串口助手发送的内容显示在 `MODE → SEND FROM PC` 视图里。
接收用环形缓冲（中断写、主循环读），支持退格，`\r\n` 只当一次换行。串口助手继续用 Type-C 口，
不需要额外的 AtoC 线。

## 7. 小游戏（小恐龙跳仙人掌）

菜单里的 `GAME` 页面。两行都用来显示画面，不占一行放分数（分数留到最后再加）：

```
第 1 行：飘过去的云，以及跳起来时出现在这里的恐龙
第 2 行：地面（'_'）上的恐龙和仙人掌
```

- 逻辑在 `dino_game.c`：世界是一条无限长的地面线，物体带"世界列坐标"；恐龙固定站在第 2 列。跳一次画到第 1 行（腾空），仙人掌从它脚下走过去就安全了，落地后才能再跳。
- **速度是渐进的**：滚动和逻辑步解耦，用累加器控制——速度从 0.5 格/拍（原来的半速，两拍才滚一格）起步，每 90 拍（约 6.3 秒）加 1/16 格/拍，约 50 秒爬到 1 格/拍封顶。逻辑步长不变，所以跳跃的墙钟时间始终是 280 ms，手感不随速度变。
- **跳跃按"格"算而不是按拍算**：一次跳跃护住 6 格（世界滚动 6 列），高速档（1 格/拍）约 420 ms、低速档（0.5 格/拍）约 840 ms。这样不管快慢，一次跳跃护住的距离一样，容错稳定；连着的 3 根仙人掌占 3 格，6 格里留了 3 格余量。
- **仙人掌有高矮**：矮的只占字符格下半部分，高的占满 8 行；两者都只需跳过去（判定按列，和高度无关）。
- **成组出现**：一丛随机 1~3 根，同一丛高矮一致；两丛之间保证 8~12 格**空地**（等待格数里把丛宽算进去），所以 3 连也不会挤在一起。
- 间隔按格算，所以速度越快，来得越快。天空装饰（云/星星）是纯背景，不参与碰撞。
- **计分**：仙人掌从恐龙身后走过去（跨过恐龙那一列）+1 分，分数右对齐显示在第 1 行最右边三格；每根仙人掌只经过那一列一次，不会重复计分。
- **昼夜每 10 秒交替一次**（143 拍）：白天天空飘云，黑夜换星星、第 1 行最左边挂一个月亮，然后 10 秒后再换回来。计时按拍子走，和世界滚动速度无关。
- 精灵用满 CGRAM 8 格：槽 0 是天空装饰（云和星星**共用这一格**，由 `lcd_cgram_define_sky()` 在昼夜切换时换点阵，这样才腾得出格子给高仙人掌）、槽 1 是 ∠、槽 2/3 恐龙跑动两帧、槽 4 恐龙腾空、槽 5 矮仙人掌、槽 6 高仙人掌、槽 7 月亮，都是 5×8 点阵，定义在 `lcd_cgram.c`。
- 按键：**↑ / → 跳**（跳跃不认 OK，避免玩的时候误触），MODE / BACK / AC 退回算式界面；
  撞上后第 1 行 `GAME OVER`、第 2 行 `SCORE n RETRY`，**只有 OK 能重开**（同样防误触），
  重开后分数归零、天色回到白天。
- 整个游戏不碰 LCD 和按键（只产出两行字符），所以能在 PC 上单独编译测试。

## 9. 验证方式

- **PC 主机测试**：9 套测试直接编译仓库里真实的 `.c` 源文件（不是抄一份逻辑），
  覆盖函数模板导航、SHIFT 上档插入、光标与显示窗口、菜单提交语义、结果格式化、
  求值器（57 个用例，含复数与极坐标）、端到端"算式→求值→第 2 行文本"、历史记录翻页与环形覆盖、
  小游戏的跳跃时限与碰撞判定。
- **数值复核**：复变函数的关键数值用 Python `cmath` 独立算过再对比，不是照抄自己的输出。
- **真机验证**：烧写后逐项测试按键、屏幕、复数、极坐标、历史记录。

## 10. 已知限制

- 反三角（asin/acos/atan）未实现。
- 按 EXE 时不会自动补右括号（`s(30` 报 Syntax ERROR，需要自己把 `)` 补上；函数模板会自动带括号）。
- 不允许隐式乘法：`2i` 必须写成 `2*i`。
- 结果精度受 float 限制，约 7 位有效数字。
- 小游戏的逻辑步长（70 ms）、跳跃时长（4 步）、仙人掌间隔（6–10 步）都是先按估算定的，需要在真机上试手感后再调；LCD 每次刷的是整屏（作者库只提供整屏写），实测一帧够快才维持现在的帧率。
